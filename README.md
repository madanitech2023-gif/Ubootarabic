# U-Boot v2026.10 — شرح شامل باللغة العربية

مرحباً، هذا المشروع يحتوي على مصدر U-Boot الإصدار 2026.10، وهو نسخة من نظام التمهيد الشهير المستخدم في الأنظمة المدمجة واللوحات الإلكترونية والأجهزة المخصصة.

U-Boot هو برنامج تحميل/BOOTLOADER يُستخدم لتهيئة المعالج والذاكرة والبطاقات والأجهزة المختلفة قبل تشغيل نظام التشغيل. وهو شائع جداً في الأنظمة المدمجة مثل ARM, PowerPC, RISC-V، وغيرها.

---

## 1) ما هو U-Boot؟

U-Boot هو اختصار لـ "Universal Boot Loader".

وظائفه الأساسية تشمل:

- تهيئة الأجهزة الأساسية مثل المعالج والذاكرة والـ DRAM.
- قراءة إعدادات التمهيد من الذاكرة أو الأجهزة الخارجية.
- تحميل نواتج نظام التشغيل مثل Linux أو Android أو FreeBSD.
- دعم واجهات تخزين مثل SD، eMMC، SPI Flash، NAND، NOR، USB.
- توفير واجهة أوامر تفاعلية عبر UART/serial أو الشبكة.
- دعم تكوينات مختلفة للوحة أو الجهاز المستهدف.

ببساطة: عندما يتم تشغيل الجهاز، يبدأ U-Boot أولاً، ثم يقوم بتهيئة النظام ثم يحمّل kernel أو ملف النظام المناسب.

## 2) ما الذي يوجد في هذا المشروع؟

في هذا العمل، تم تحميل كود مصدر U-Boot في المجلد التالي:

- `u-boot-v2026.10`

هذا المجلد يحتوي على الكود المصدري الكامل لـ U-Boot، بما في ذلك:

- كود التهيئة الأساسية للمعالجات.
- دعم اللوحات والأجهزة المختلفة.
- ملفات تكوين اللوحات (`configs/`).
- ملفات تعريف الأجهزة (`dts/`).
- دعم برامج التشغيل (`drivers/`).
- ملفات رؤوس (`include/`).
- مكتبات النظام (`lib/`).
- ملفات تهيئة البناء (`Makefile`, `Kconfig`, `config.mk`).

## 3) هيكل المشروع الرئيسي

فيما يلي أهم مجلدات المشروع:

### `arch/`
يحتوي هذا المجلد على دعم المعالجات والعمارة المختلفة مثل:

- ARM
- x86
- MIPS
- RISC-V
- PowerPC
- sandbox
- وغيرها

### `board/`
يحتوي على دعم اللوحات والأجهزة الخاصة لكل منصة، مثل:

- بطاقات تطوير
- لوحات SoC
- أجهزة صناعية
- لوحات ARM وRISC-V

### `configs/`
يحتوي على ملفات تعريف اللوحة، مثل:

- `myboard_defconfig`
- `qemu_arm_defconfig`
- `rk3399_defconfig`
- وغيرها

كل ملف تعريف يحدد إعدادات بناء معينة للوحة أو البنية.

### `drivers/`
يحتوي على برامج التشغيل للأجهزة مثل:

- USB
- SPI
- I2C
- GPIO
- MMC / SD
- Ethernet
- Flash

### `include/`
يحتوي على ملفات الرأس والواجهات العامة والمكتبات الأساسية المستخدمة داخل النظام.

### `dts/`
يحتوي على ملفات شجرة الأجهزة Device Tree، وهي وصف للهياكل الإلكترونية داخل الجهاز.

### `scripts/`
يحتوي على أدوات ومنطق التشغيل الخاص بالبنية والكتابة والإنشاء والتجميع.

### `tools/`
يحتوي على أدوات مساعدة تُستخدم أثناء البناء أو التصحيح أو التوليد.

## 4) كيفية بناء U-Boot

قبل البناء، تحتاج إلى إعداد بيئة تطوير مناسبة.

### المتطلبات الأساسية

- GNU Make
- GCC أو Cross Compiler مناسب
- binutils
- Git
- bash أو shell Linux
- بعض المكتبات المطلوبة حسب المنصة

### مثال أساسي للبناء

افتح الطرفية ثم انتقل إلى مجلد المشروع:

```bash
cd /workspaces/Ubootarabic/u-boot-v2026.10
```

اختيار تكوين لوحة معينة:

```bash
make <board>_defconfig
```

مثلاً:

```bash
make qemu_arm_defconfig
```

أو لوحة أخرى حسب الجهاز الذي تعمل عليه.

ثم ابدأ التجميع:

```bash
make -j$(nproc)
```

سيتم إنشاء ملف الإخراج النهائي مثل:

- `u-boot`
- `u-boot.bin`
- `u-boot.img`

اعتماداً على البنية والخيارات.

---

## 5) استخدام Cross Compiler

إذا كنت تبني لواجهة ARM أو SoC معين، فغالباً تحتاج إلى cross compiler.

مثال:

```bash
export CROSS_COMPILE=arm-linux-gnueabihf-
make <defconfig>
make -j$(nproc)
```

أو مثال آخر:

```bash
export CROSS_COMPILE=aarch64-linux-gnu-
make qemu_arm64_defconfig
make -j$(nproc)
```

الـ `CROSS_COMPILE` يحدد البادئة التي يستخدمها المترجم عبر النظام.

## 8) كيف يتم تشغيل U-Boot؟

بعد بناء U-Boot، يتم عادة كتابة الملف إلى:

- بطاقة SD
- Flash SPI
- NAND/NOR Flash
- eMMC

ثم عند التمهيد، يبدأ الجهاز من هذا bootloader ويقوم بتحميل kernel أو تطبيقات أخرى.

وبشكل عام، في الأنظمة المدمجة، يكون U-Boot هو أول برنامج يشتغل بعد الطاقة.

---

## 9) ملف Makefile وKconfig

### Makefile
هو الملف الأساسي للبناء. يحدد:

- الأهداف
- المكتبات
- إعدادات التجميع
- ملفات المصدر
- خطوات التوليد

### Kconfig
هو نظام إعدادات تهيئة المشروع، ويتيح لك:

- تعديل الخيارات
- تفعيل أو إلغاء مكونات معينة
- تخصيص ميزات النظام

من خلال:

```bash
make menuconfig
```

---

## 10) ما أهمية Device Tree؟

يُستخدم Device Tree لوصف الأجهزة الموجودة على اللوحة، مثل:

- المعالج
- الذاكرة
- المنفذ التسلسلي
- USB
- GPIO
- Ethernet
- I2C
- SPI

هذا يساعد U-Boot على معرفة كيفية تهيئة النظام بشكل صحيح لكل جهاز.

---

## 11) لماذا U-Boot مهم؟

U-Boot مهم لأنّه:

- يهيئ النظام قبل أن يعمل kernel.
- يدعم التحميل الآمن والتهيئة المتقدمة.
- يعمل على مختلف الأنظمة والهياكل.
- يسمح بالتخصيص للوحة المعينة.
- مهم في تطوير الأنظمة المدمجة والـ embedded systems.
